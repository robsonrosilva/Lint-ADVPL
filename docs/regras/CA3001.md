# CA3001 — A diretiva de inclusão deve estar em caixa baixa

| | |
| --- | --- |
| **Identificador** | `CA3001` |
| **Origem** | `totvs` — catálogo oficial |
| **Grupo** | G3 — Legacy and Deprecated Code |
| **Severidade no catálogo** | `MINOR` |
| **Severidade exibida** | `Hint` — sobreposição da tabela, por volume medido (ver abaixo) |
| **Chave de configuração** | `advplLint.rules.CA3001` |
| **Fonte** | `referencias/totvs/sonarqube-rules-reference.md`, linha 53, release `v1.0.1`, consultada em 2026-08-19 |

## O que a regra pega

Diretiva de inclusão cujo nome não está inteiramente em caixa baixa.

```advpl
#INCLUDE "TOTVS.CH"     // reprova
#Include "TOTVS.CH"     // reprova
#InClUdE "protheus.ch"  // reprova
#include "totvs.ch"     // correto
```

O intervalo do diagnóstico cobre **apenas o token da diretiva** — do `#` ao fim da palavra. Sublinhar
a linha inteira esconderia onde está o problema.

## O que a regra NÃO pega

Ocorrências que não são código:

```advpl
// Nao usar #INCLUDE em caixa alta neste projeto.   <- comentário de linha
/*
   Bloco citando #INCLUDE "TOTVS.CH" de proposito.  <- comentário de bloco
*/
Local cTexto := "#INCLUDE dentro de aspas"          <- literal de texto
```

Esse é o único falso positivo plausível da regra, e tem fixture dedicada em
`packages/server/test/fixtures/ca3001-comment-and-string.prw`.

A regra também **não** olha o nome do arquivo incluído. `#include "TOTVS.CH"` — diretiva em caixa
baixa, arquivo em caixa alta — não é violação de `CA3001`.

## Como corrigir

Escreva a diretiva em caixa baixa:

```advpl
#include "totvs.ch"
```

## Por que `Hint` e não `Information`

A tabela versionada mapeia `MINOR` do catálogo para `Information`, e continua certa como **tradução
da severidade**. Esta regra sobrepõe a tabela por um segundo eixo, que ela não enxerga: **volume**.

Medição de 2026-08-19, sobre 6.000 fontes reais do corpus:

| | |
| --- | --- |
| Diretivas `#include` encontradas | 15.306 |
| Em caixa alta — violam `CA3001` | **11.006 (71,9%)** |

Como `Information`, uma única regra `MINOR` de estilo dominaria o painel de problemas de qualquer
projeto Protheus real. O Princípio III é explícito: regra ruidosa treina o usuário a ignorar o painel
inteiro. Como `Hint`, a violação continua marcada no código e a ação de correção continua oferecida —
só não entulha a lista.

A sobreposição exige razão registrada no código, e o registro de regras **rejeita** sobreposição sem
justificativa.

## Por que isso importa

O catálogo da TOTVS classifica a regra em **G3 — Legacy and Deprecated Code**. Caixa alta na diretiva
é herança de fonte antigo; padronizar em caixa baixa mantém o código alinhado ao que a TOTVS revisa e
evita divergência entre fontes do mesmo projeto.

## Como desligar

```jsonc
{
  // Desliga a regra por completo
  "advplLint.rules.CA3001.enabled": false,

  // Ou eleva a severidade exibida, se o time quiser tratar como aviso
  "advplLint.rules.CA3001.severity": "warning"
}
```

## Notas de implementação

- **Custo**: uma passagem pelas linhas, sem estado entre elas. Em cada linha, o trabalho é pular o
  recuo e comparar uma palavra — o texto da linha não é varrido.
- **Codificação**: o intervalo é calculado sobre texto decodificado como CP1252. Bytes da faixa
  `0x80`–`0x9F` (travessão, aspas tipográficas, euro) não deslocam a posição. Ver
  `packages/server/test/fixtures/ca3001-cp1252-highrange.prw`.
- **Fim de linha**: CRLF, LF e os dois misturados no mesmo arquivo produzem a mesma numeração de
  linha.
